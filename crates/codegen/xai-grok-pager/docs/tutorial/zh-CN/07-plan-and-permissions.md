# 计划模式与权限

Grok 在做有风险的事前会先问你 — 也可以先规划再写代码。

## 权限

当 Grok 想跑有风险的命令或编辑文件时，会暂停并询问：
允许一次、始终允许这类操作，或拒绝。

读取始终免费：读文件、搜索，以及安全的只读命令
（`ls`、`git status`、`grep` 等）不会弹窗。链式命令会逐段检查 —
`ls && rm -rf tmp` 仍会为 `rm` 征求许可。

信任这个会话？`/always-approve`（或 `Ctrl+O`）会跳过提示。

## 计划模式

任务更大或更含糊时，用**计划模式**：Grok 只读探索代码库，
设计方案，并在写任何代码*之前*把计划交给你批准。

- **`Shift+Tab`**（焦点在提示框）循环模式：普通 → 计划 → 始终批准。
- **`/plan`** 直接进入计划模式；`/plan <task>` 一步规划该任务。

计划就绪后：`a` 批准，`c` 对某一行评论，`s` 要求修改 —
Grok 会迭代到你满意，然后再实现。

好习惯：问「到底该怎么做」用计划模式，问「直接做」用普通模式。

## 长时间命令

构建或测试占着回合？**`Ctrl+B`** 把它转到后台 —
Grok 继续工作，完成后通知你（`Ctrl+G` 打开任务面板）。
